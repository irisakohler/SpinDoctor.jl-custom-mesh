# SpinDoctor.jl for simulations with multi-compartment meshes

> This repository is a modified fork of the original
> [SpinDoctor.jl](https://github.com/spindoctormri/SpinDoctor.jl)
> project

The original SpinDoctor.jl package provides finite-element-based diffusion MRI
(dMRI) simulations.

This fork extends the original implementation to support the custom 2D multi-compartment mesh
representation generated by the image-based meshing pipeline described in the
associated histology-to-mesh workflow repository available at: [https://github.com/irisakohler/histology-image-to-mesh](https://github.com/irisakohler/histology-image-to-mesh)

    ↓

    ↓

    ↓

## Custom simulation driver

This fork introduces a custom simulation driver for running diffusion MRI
simulations directly on image-derived compartment meshes.

File:
```text
examples/custom_driver.jl
```

The driver:

1. loads custom 2D meshes generated by the preprocessing pipeline,
2. identifies extracellular/background compartments,
3. constructs SpinDoctor geometry and coefficient structures,
4. assembles finite-element matrices,
5. solves the Bloch–Torrey PDE,
6. computes the dMRI signal,
7. exports magnetization fields and simulation metadata.

---

### Expected mesh structure

Each mesh directory must contain:

```text
mesh.node
mesh.ele
mesh.face
mesh_metadata.json
```

where:
- `mesh.node` contains 2D node coordinates,
- `mesh.ele` contains triangular elements and compartment labels,
- `mesh.face` stores compartment interface edges,
- `mesh_metadata.json` stores auxiliary metadata such as:
  ```json
  {
      "n_background": 4
  }
  ```

The driver assumes that:
- the first `n_background` compartments correspond to extracellular regions,
- all remaining compartments correspond to intracellular domains.

Here, the `.face` file differs from the standard TetGen/Triangle format and has the following row-wise structure:

```text
<edge_id> <node1> <node2> <boundary_marker> <region_a> [region_b]
```

where:
- external boundaries contain one adjacent region,
- internal interfaces contain two adjacent regions.


---

### Magnetization CSV output format

Simulation fields are exported as CSV files using:

```text
src/postprocess/savefield_csv.jl
```

Each row corresponds to a mesh point/node together with the simulated complex magnetization and compartment/interface metadata.

The exported columns are:

| Column | Description |
|---|---|
| `X` | x-coordinate |
| `Y` | y-coordinate |
| `Z` | z-coordinate (`0` for 2D simulations) |
| `magnetization_real` | real part of the complex magnetization |
| `magnetization_imag` | imaginary part of the complex magnetization |
| `is_interface` | `1` if the point lies on a compartment interface, otherwise `0` |
| `is_interior_point` | `1` for interior points, otherwise `0` |
| `parameter_value` | diffusivity for interior points or permeability for interface points |
| `signal` | absolute value of the integrated dMRI signal (same value repeated for all rows in the file) |

## Batch execution

File:
```text
examples/execute_driver_parallel.sh
```

This script automates large-scale simulations across many small domains.

The workflow:
1. scans a parent directory containing mesh subdirectories,
2. launches one simulation job per patch,
3. distributes jobs across CPU cores using `xargs`,
4. stores logs and outputs separately for each patch.

The script was designed for high-throughput simulation of tiled histology-derived datasets.
